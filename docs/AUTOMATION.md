# Development and review

Use owner-started runs and existing owner-configured automation; do not create or change development schedules without an explicit request. Subscription limits stop work; never fall back to an OpenAI API key.

The automatic developer follows the seven-step cycle in `AGENTS.md`: reconcile unfinished work, handle PR findings, merge eligible earlier-run PRs, fix issues/maintenance, develop scoped roadmap items, maintain documentation, and repeat while useful work is actionable. Critical defects take priority; blocked work does not prevent independent progress. Stop rather than wait when only external checks or required input remain. Do not overlap runs writing to the same checkout. Multiple focused PRs may stay open. Independent changes use separate branches. At the start of each run, inspect existing PRs: merge only those with finished current-head Codex review, passing required CI, and handled comments. Fix or reject findings as appropriate; do not wait for pending checks just to merge later in the same run. Newly created or updated PRs stay open until the next run. Do not queue auto-merge to merge while the agent is idle.

Codex suggestions are not mandatory. The agent judges whether they improve correctness, security, or intended behavior, then either commits/pushes a tested fix or records a concrete rejection reason in the conversation. Resolve conversations only after handling the finding. A new push requires new review/checks; never weaken checks or create no-op pushes.

The owner configured the existing automatic review integration to review each push. Development agents can implement fixes and merge eligible PRs using GitHub tools. No additional local reviewer, security scheduler, custom status publisher, merge bot, or OpenAI API job is needed. GitHub authors cannot formally approve their own PRs.

Use the versioned Swift CodeQL workflow (advanced setup). Keep the native tests/app build, Swift CodeQL and resolved-conversation protections. The native job also exercises workflow-helper regressions. CI does not prove a review occurred: verify the latest-head review and comment decisions under `AGENTS.md` before merging, without bypassing protections.

The native-tooling transition removes obsolete reference-package jobs. Keep current branch protections unchanged while that PR is under development/review. Once its current-head review, native tests/app build and full Swift extraction/coverage checks pass, reconcile required contexts with the workflows actually present in that reviewed tree before merging; preserve strict up-to-date checks, native/security requirements, conversation resolution and administrator enforcement. Do not publish substitute/no-op statuses or disable valid requirements to hide failures. Recheck other open PRs against the native baseline after it merges.
