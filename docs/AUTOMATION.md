# Development and review

Use owner-started runs and existing owner-configured automation; do not create or change development schedules without an explicit request. Subscription limits stop work; never fall back to an OpenAI API key.

Before selecting work, follow `AGENTS.md`'s roadmap reconciliation: refreshed master baseline, actual open-PR scope, and relevant branch/worktree changes and PR history. Record Planned/In progress/Merged with ownership evidence; an old checkout or a branch name alone cannot establish that a task is free or finished.

The automatic developer follows the seven-step cycle in `AGENTS.md`: reconcile unfinished work, handle Codex and CodeRabbit findings and historical unresolved feedback, monitor review/CI, merge eligible PRs, fix issues/maintenance, develop roadmap items and maintain documentation. Critical defects take priority; blocked work does not prevent independent progress. Do not overlap runs writing to the same checkout or with an active CodeRabbit autofix task. Multiple focused PRs may stay open; independent changes use separate branches. Monitor pending work at bounded intervals and handle new findings until eligible PRs can merge, including PRs updated in the current run. Stop for required owner input, persistent service/authentication failures or usage limits.

Codex and CodeRabbit suggestions are not mandatory. The agent judges whether they improve correctness, security, or intended behavior, then either commits/pushes a fix with regression coverage verified by post-review CI or records a concrete rejection reason in the conversation. Resolve conversations only after handling the finding. A new push requires new review/checks; disable any queued auto-merge before updating. Never weaken checks or create no-op pushes.

CodeRabbit reviews every push and approves the latest reviewed commit after its feedback is resolved. Keep the Codex review bot enabled. Both reviews must finish on the same current head, with findings handled before CI. Codex also continues as the developer. `.coderabbit.yaml` keeps incremental reviews and automatic approval enabled. No new reviewer, scheduler, status publisher or merge bot is added.

PR CI (`ci.yml`) starts on every push, in parallel with Codex and CodeRabbit: a Linux job classifies the diff, then the native job runs on Apple Silicon (`macos-15`). The separate review-gate workflow (`review.yml`) runs on submitted/dismissed reviews; its required Change scope job validates the latest CodeRabbit decision and Codex SHA-bearing clean-completion summary against the event and live PR head and requires all review threads resolved (paginated). It blocks merging, not testing. Missing data, stale approvals and classification errors fail closed: if classification fails, the required native job still starts and fails its first step, because a skipped required job would count as passing. A new push needs both reviews again before merge; its tests start immediately.

PRs package the debug build that `swift test` already compiled (`STUDSYNC_BUILD_CONFIGURATION=debug`) and run the same bundle assertions; master pushes and release tags always build release. On a master push, `script/pr_tested_tree.sh` skips tests and fixtures only when the squash-merge tree is identical to the merged PR head and that head's PR CI native job passed; the release bundle is still rebuilt and verified. Any lookup failure runs the full job. The native job caches `.build` per configuration and `Package.resolved`; it is never used by CodeQL or release builds. Delete the Actions cache if an incremental build misbehaves.

CodeQL (`codeql.yml`, reusable) runs on master pushes that change code, the weekly scan, and in the release workflow before any draft is created. It stays on `macos-15-intel` (the CodeQL tracer needs Rosetta on Apple Silicon) with a clean, uncached traced build and the first-party source coverage check. PRs do not run CodeQL.

The pre-push hook (`.githooks/pre-push` → `script/pre_push.sh`, enabled with `git config core.hooksPath .githooks`) runs `swift test` locally unless every pushed ref only changes allowlisted documentation. It refuses to push a branch commit other than the checked-out `HEAD` (check that branch out first) and refuses to test with uncommitted tracked changes or untracked files under `Sources/`, `Tests/` or `Package.*`; release tag pushes skip the local run. Hosted CI stays authoritative; the local Swift toolchain can be newer than CI's Xcode 16.4.

Before merging, inspect the actual current-head Codex clean summary plus 👍, CodeRabbit approval, feedback decisions, resolved conversations and required Change scope/native/CodeRabbit checks. Preserve the SHA-matched immediately-mergeable auto-merge procedure in `AGENTS.md`; do not leave deferred auto-merge enabled. A successful CodeRabbit check alone can mean skipped/rate-limited work and is insufficient. Authors cannot formally approve their own PRs.

Use the versioned Swift CodeQL workflow (advanced setup). Keep the native tests/app build, Swift CodeQL and resolved-conversation protections. The native job also exercises workflow-helper regressions. CI does not prove a review occurred: verify the latest-head review and comment decisions under `AGENTS.md` before merging, without bypassing protections.
