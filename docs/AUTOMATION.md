# Development and review

Use owner-started runs and existing owner-configured automation; do not create or change development schedules without an explicit request. Subscription limits stop work; never fall back to an OpenAI API key.

Before selecting work, follow `AGENTS.md`'s roadmap reconciliation: refreshed master baseline, actual open-PR scope, and relevant branch/worktree changes and PR history. Record Planned/In progress/Merged with ownership evidence; an old checkout or a branch name alone cannot establish that a task is free or finished.

The automatic developer follows the seven-step cycle in `AGENTS.md`: reconcile unfinished work, handle CodeRabbit findings and historical unresolved feedback, monitor review/CI, merge eligible PRs, fix issues/maintenance, develop roadmap items and maintain documentation. Critical defects take priority; blocked work does not prevent independent progress. Do not overlap runs writing to the same checkout or with an active CodeRabbit autofix task. Multiple focused PRs may stay open; independent changes use separate branches. Monitor pending work at bounded intervals and handle new findings until eligible PRs can merge, including PRs updated in the current run. Stop for required owner input, persistent service/authentication failures or usage limits.

CodeRabbit suggestions are not mandatory. The agent judges whether they improve correctness, security, or intended behavior, then either commits/pushes a fix with regression coverage verified by post-review CI or records a concrete rejection reason in the conversation. Resolve conversations only after handling the finding. A new push requires new review/checks; disable any queued auto-merge before updating. Never weaken checks or create no-op pushes.

CodeRabbit reviews every push and approves the latest reviewed commit after its feedback is resolved. The owner disables the Codex review integration; no Codex review or reaction is required. Codex continues as the developer. `.coderabbit.yaml` keeps incremental reviews and automatic approval enabled. No new reviewer, scheduler, status publisher or merge bot is added.

PR CI is triggered by submitted/dismissed reviews. The required Change scope job validates the latest CodeRabbit decision against the event and live PR head, requires all review threads resolved (paginated), then classifies the diff. Before approval this inexpensive check fails; macOS jobs do not start. Missing data, stale approvals and classification errors fail closed. Master pushes and the existing weekly scan remain enabled. No automated checks or CodeQL run locally. A new push needs another CodeRabbit review and post-review CI.

Before merging, inspect the actual current-head CodeRabbit approval, feedback decisions, resolved conversations and required Change scope/native/CodeQL/CodeRabbit checks. Preserve the SHA-matched immediately-mergeable auto-merge procedure in `AGENTS.md`; do not leave deferred auto-merge enabled. A successful CodeRabbit check alone can mean skipped/rate-limited work and is insufficient. Authors cannot formally approve their own PRs.

Use the versioned Swift CodeQL workflow (advanced setup). Keep the native tests/app build, Swift CodeQL and resolved-conversation protections. The native job also exercises workflow-helper regressions. CI does not prove a review occurred: verify the latest-head review and comment decisions under `AGENTS.md` before merging, without bypassing protections.
