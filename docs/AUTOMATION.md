# Development and review

Use owner-started runs and existing owner-configured automation; do not create or change development schedules without an explicit request. Subscription limits stop work; never fall back to an OpenAI API key.

Before selecting work, follow `AGENTS.md`'s roadmap reconciliation: refreshed master baseline, actual open-PR scope, and relevant branch/worktree changes and PR history. Record Planned/In progress/Merged with ownership evidence; an old checkout or a branch name alone cannot establish that a task is free or finished.

The automatic developer follows the seven-step cycle in `AGENTS.md`: reconcile unfinished work, handle both bots' findings, monitor review/CI, merge eligible PRs, fix issues/maintenance, develop roadmap items and maintain documentation. Critical defects take priority; blocked work does not prevent independent progress. Do not overlap runs writing to the same checkout or with an active CodeRabbit autofix task. Multiple focused PRs may stay open; independent changes use separate branches. Monitor pending work at bounded intervals and handle new findings until eligible PRs can merge, including PRs updated in the current run. Stop for required owner input, persistent service/authentication failures or usage limits.

Codex and CodeRabbit suggestions are not mandatory. The agent judges whether they improve correctness, security, or intended behavior, then either commits/pushes a tested fix or records a concrete rejection reason in the conversation. Resolve conversations only after handling the finding. A new push requires new review/checks; disable any queued auto-merge before updating. Never weaken checks or create no-op pushes.

The existing Codex integration and owner-installed CodeRabbit review pushes. `.coderabbit.yaml` enables incremental reviews without automatic pausing, review-error failures, automatic approvals after feedback is resolved, and AGENTS/SECURITY guidance. It does not publish a custom status or merge PRs. CodeRabbit's [automatic approval](https://docs.coderabbit.ai/pr-reviews/automatic-approvals) is separate from GitHub auto-merge. No additional local reviewer, security scheduler, custom status publisher, merge bot or OpenAI API job is needed. GitHub authors cannot formally approve their own PRs.

Before enabling GitHub auto-merge, verify the current SHA in Codex's completed no-findings summary plus its 👍, a completed current-head CodeRabbit approval with no outstanding feedback, all required checks passing, and resolved required conversations. A successful [CodeRabbit check](https://docs.coderabbit.ai/pr-reviews/status-check) alone can also mean skipped/rate-limited work and is insufficient. Recheck the head and that GitHub reports the PR immediately mergeable, then use `gh pr merge --auto --squash --match-head-commit <sha>` and confirm the merge. That SHA protects the request when issued, not a future queued merge. If the request stays queued, disable it and continue monitoring; do not allow a deferred request to survive into a different head. A Codex reaction cannot be required natively by GitHub: the agent checks it before enabling auto-merge; branch protection alone does not enforce this evidence. New commits invalidate eligibility.

Use the versioned Swift CodeQL workflow (advanced setup). Keep the native tests/app build, Swift CodeQL and resolved-conversation protections. The native job also exercises workflow-helper regressions. CI does not prove a review occurred: verify the latest-head review and comment decisions under `AGENTS.md` before merging, without bypassing protections.
